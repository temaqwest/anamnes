# Anamnes

Личный архив анализов, обследований, врачебных заключений и лекарств. Веб-клиент на React, TypeScript, Vite и shadcn/ui работает в настольном и мобильном браузерах и поддерживает запуск как PWA. API работает на Django REST Framework. [Требования к приложению](https://chatgpt.com/space/page_758ecdde86408191a52531d6f5e236d1).

## Запуск в Docker

Понадобится Docker с Compose v2. Из корня проекта скопируйте `.env.example` в `.env`. Заполните `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD` двумя разными случайными значениями. Не добавляйте `.env` в репозиторий.

```sh
docker compose up --build -d --wait
docker compose exec api python manage.py createsuperuser
```

Откройте [Anamnes](http://127.0.0.1:5186) и войдите под созданной учётной записью. Если порт занят, задайте `ANAMNES_PORT` в `.env`. Миграции и обработчик текстов запускаются автоматически. Python, Node.js и зависимости устанавливаются внутри образов.

- `docker compose logs -f api indexer` показывает журналы API и обработки PDF.
- `docker compose up --build -d --wait` пересобирает приложение после изменений.
- `docker compose down` останавливает проект и сохраняет именованные тома `postgres` и `originals`. Для резервной копии нужны оба тома. Флаг `--volumes` удаляет их.

Compose создаёт отдельный архив в PostgreSQL. Для существующего архива SQLite доступна [инструкция переноса базы и оригиналов PDF](docs/archive-transfer.md).

### PWA на телефоне

Откройте Anamnes по HTTPS. В Chrome выберите установку приложения в меню браузера, в Safari воспользуйтесь меню «Поделиться» и добавлением на экран «Домой». Для Docker направьте доверенный HTTPS-прокси на `127.0.0.1:5186`. Прокси должен сохранять исходный `Host` и сам устанавливать `X-Forwarded-Proto: https`. Настройте `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS` и `DJANGO_SECURE_COOKIES=1` по примеру в `.env.example`. В офлайне отображается страница состояния сети. [Установка PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)

## Запуск для разработки без Docker

Понадобятся Python 3.12 или новее и Node.js 22.18 или новее. Из корня проекта запустите бэкенд:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
.venv/bin/python backend/manage.py migrate
.venv/bin/python backend/manage.py createsuperuser
.venv/bin/python backend/manage.py runserver 127.0.0.1:8000
```

Во втором терминале запустите веб-клиент:

```sh
cd frontend
npm ci
npm run dev
```

Откройте [Anamnes](http://127.0.0.1:5186) и войдите под созданной учётной записью.

### Регистрация по приглашению

При локальном запуске Django режим приглашений включён. Из корня проекта создайте ссылку для тестового адреса:

```sh
.venv/bin/python backend/manage.py create_invite patient@example.test
```

Откройте полученную ссылку, введите тот же email и придумайте пароль. Письмо подтверждения появится в терминале Django. После подтверждения можно войти по email и проверить восстановление доступа через «Забыли пароль?». Ссылка-приглашение действует семь дней, письма с подтверждением и сбросом пароля — один час.

В Compose регистрация по умолчанию выключена. Для локальной проверки задайте в `.env` `ANAMNES_SIGNUP_ENABLED=1`, `ANAMNES_PUBLIC_URL=http://127.0.0.1:5186` и `DJANGO_EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend`, затем перезапустите Compose. Создайте приглашение командой `docker compose exec api python manage.py create_invite patient@example.test`. Письма видны в `docker compose logs api`. Для размещения укажите фактический HTTPS-адрес и настройки SMTP из `.env.example`. [ADR о регистрации](docs/adr/0017-invite-registration.md)

Локально используется SQLite. Для подключения PostgreSQL задайте `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` и при необходимости `POSTGRES_HOST` и `POSTGRES_PORT` перед запуском Django. Оригиналы хранятся в `backend/private-media/` и выдаются через API с проверкой владельца. Для поиска по тексту после `migrate` запустите обработчик в отдельном терминале:

```sh
.venv/bin/python backend/manage.py index_documents
```

Флаг `--once` обрабатывает очередь и завершает процесс. Флаг `--retry-failed` повторно ставит ошибки извлечения в очередь. Для Compose те же параметры можно передать командой `docker compose exec api python manage.py index_documents --retry-failed --once`.

В Docker Poppler и Tesseract с русским и английским языками уже в образе. Для повторного распознавания ранее обработанных PDF, в том числе смешанных, запустите `docker compose exec indexer python manage.py index_documents --retry-no-text --retry-ready --once`. При запуске без Docker эти инструменты нужны для OCR. [Распознавание сканов](docs/adr/0012-ocr.md)

## Первый сценарий

- В меню «Тема оформления» можно выбрать светлую или тёмную тему либо использовать настройку устройства. Выбор сохраняется в браузере.
- Добавьте до 10 PDF размером до 25 МБ каждый. Даты распознаются в сегментах имени, разделённых `_`. Поддерживаются варианты `2025-03-14`, `2025.03.14`, `14.03.2025` и `14-03-2025`.
- Сверьте исходное имя, дату, название процедуры и области. Если имя содержит однозначную фразу, например «ЭКГ», область уже отмечена. Спорные совпадения можно принять одним нажатием. Любую отметку можно снять или добавить вручную. Для сохранения нужны дата и название.
- Назначьте документу категорию «Заключение врача», «Обследование» или «Анализ». Иконка и цвет видны в архиве, а категорию можно исправить из просмотра. Фильтр по категории работает в списке и на таймлайне, в том числе для документов без категории.
- Создайте свою область кнопкой «Добавить область» в карточке загрузки. В разделе «Предметные области» можно добавить область, изменить название и заполнить необязательную подсказку до 300 символов. Подсказка открывается по значку информации.
- Найдите документ по названию, имени файла или тексту PDF. По совпадению внутри PDF архив показывает фрагмент и открывает нужную страницу. Статус извлечения можно обновить кнопкой в архиве.
- Откройте PDF и переключите страницу. Метаданные можно отредактировать из просмотра.
- Отметьте два исследования в архиве и нажмите «Сравнить два PDF». В каждой панели можно переключить документ, выбрать его из текущей подборки и изменить масштаб просмотра.
- Чекбокс в шапке списка отмечает все показанные исследования. «Удалить выбранные» удаляет отмеченные файлы и их записи, а «Удалить все документы» очищает архив независимо от фильтров. Обе операции требуют подтверждения.
- Переключитесь на «Таймлайн», выберите месяц из списка или переключите его стрелками, затем нажмите на отметку дня. Из списка исследований за этот день можно открыть PDF.
- В разделе «Лекарства» добавьте регулярный или разовый приём. Кнопка «В историю» переносит запись со сведениями о приёме в историю.

## Разработка

- [Журнал архитектурных решений](docs/adr/README.md) объясняет выбор стека, структуру фронтенда, импорт, поиск и развёртывание.
- Фронтенд организован по Feature-Sliced Design. Экраны находятся в `frontend/src/pages`, общие данные исследования — в `frontend/src/entities/study`, компоненты shadcn/ui — в `frontend/src/shared/ui`. Границы и правила импортов описаны в [ADR 0002](docs/adr/0002-feature-sliced-design.md).
- Если файловое хранилище было недоступно при удалении PDF, после восстановления запустите `docker compose exec api python manage.py cleanup_deleted_originals` или `.venv/bin/python backend/manage.py cleanup_deleted_originals` при запуске без Docker. [ADR 0014](docs/adr/0014-document-deletion.md)
