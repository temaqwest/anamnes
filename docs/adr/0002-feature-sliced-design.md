# ADR 0002. Feature-Sliced Design для фронтенда

**Статус — принято.** 23 ноября 2026 года.

## Контекст

Архив, загрузка, просмотр и сравнение используют общие данные исследования. Загрузка и просмотр используют общие поля формы. Для ручной разработки важно быстро найти владельца кода и знать, откуда его можно импортировать.

## Решение

Используем Feature-Sliced Design с декомпозицией от страниц. Таблица описывает текущие слои.

| Слой | Что лежит в `frontend/src` |
| --- | --- |
| `app` | Точка входа, маршруты, проверка сессии, общая оболочка и стили |
| `pages` | По одному слайсу на экран: `archive`, `upload`, `document`, `compare`, `medications`, `sign-in`. Состояние форм и логика отдельных экранов живут в соответствующих страницах |
| `features` | Диалог управления предметной областью, общий для архива и загрузки |
| `entities` | `study` хранит типы, запросы и общие поля исследования. `session` содержит контракт браузерной сессии |
| `shared` | HTTP-клиент, компоненты shadcn/ui, просмотрщик PDF и утилита классов |

- Зависимости идут от `app` через `pages`, `features` и `entities` к `shared`. Между слайсами одного слоя прямые импорты запрещены.
- Из другого слайса импортируем через его `index.ts` и алиас `@/`. Внутри слайса используем относительный путь до модуля. Из `shared/ui` импортируем нужный компонент по имени.
- Начинаем новую логику в странице. Выделяем `features` для переиспользуемого пользовательского действия и `widgets` для самостоятельного блока, когда они понадобятся нескольким экранам.
- URL хранит фильтры архива и параметры навигации. Состояние формы и запроса остаётся рядом с экраном, который им пользуется.

## Последствия

- Для изменения загрузки начинайте с `pages/upload`. Для изменения запроса или формы исследования — с `entities/study`. Для добавления компонента shadcn/ui используется путь `shared/ui` из `components.json`.
- Команда `npm --prefix frontend run lint:architecture` проверяет FSD через Steiger. Сборка отдельно проверяет типы и доступность импортов.
