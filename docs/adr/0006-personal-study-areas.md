# ADR 0006. Личные предметные области

**Статус — принято.** 23 ноября 2026 года.

## Контекст

Предметная область помогает врачу отфильтровать исследования. Начальный каталог уже используется в загруженных документах. Владелец должен иметь возможность добавлять и переименовывать области своего архива.

## Решение

- Храним предметные области пользователя в `StudyArea`. Начальный каталог служит шаблоном для новых учётных записей.
- Ссылки документов указывают на личные области. При обновлении создаём их с прежними идентификаторами и переносим существующие связи. Переименование меняет подпись области, сохраняя идентификатор и фильтр.
- API показывает и меняет области текущего пользователя. При добавлении или редактировании PDF сервер проверяет принадлежность каждой выбранной области. Названия уникальны внутри аккаунта с учётом нормализации регистра и пробелов.
- Диалог создания и переименования используется на страницах архива и загрузки через публичный API слайса `features/edit-study-area`. При создании из карточки загрузки новая область автоматически отмечается для этого файла.

## Последствия

- Один исходный каталог даёт готовый список на первом входе. Дальнейшие изменения относятся к личному архиву.
- Сохранённые фильтры по идентификаторам продолжают работать после изменения подписи. Для отката после создания личных областей нужна резервная копия базы до миграции, поскольку прежняя схема представляла общий каталог.
