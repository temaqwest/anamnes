# ADR 0013. Перенос SQLite-архива в Docker Compose

**Статус — принято.** 23 ноября 2026 года.

## Контекст

Архив при локальном запуске хранит записи в SQLite, а оригиналы — в файловой системе. При переходе на Compose данные должны сохраниться в томах `postgres` и `originals` вместе с учётными записями, связями и уже извлечённым текстом.

## Решение

- Команда `transfer_archive` читает SQLite через SQLite Backup API и применяет текущие миграции к временной копии. По умолчанию команда выполняет проверку. Запись в тома выполняется с флагом `--apply`.
- Перенос выполняется при остановленных приложениях. Команда проверяет, что целевое хранилище свободно от пользовательских записей, а затем импортирует их в одной транзакции. PostgreSQL блокирует запись в затронутые таблицы на время переноса. Связи с системными разрешениями сопоставляются по их ключам Django.
- У каждого документа проверяется путь оригинала. Команда сверяет SHA-256 файлов при копировании и публикует всё дерево `originals/` одним переименованием перед фиксацией транзакции. Если процесс был прерван после публикации файлов, пустая база может повторно использовать это дерево после проверки всех путей и хешей.

## Последствия

Пароли, права доступа, идентификаторы, метаданные, области и текст страниц сохраняются. После запуска Compose пользователи входят снова. Документы, обработка которых была прервана, возвращаются в очередь обработки. Файлы без ссылки из базы остаются в исходном архиве. Порядок действий и проверки приведены в [инструкции по переносу](../archive-transfer.md).
