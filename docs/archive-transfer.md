# Перенос локального архива в Docker Compose

Для переноса нужны Docker Compose, существующая база SQLite и каталог медиа из того же архива. При стандартном локальном запуске это `backend/db.sqlite3` и `backend/private-media/`. В целевой базе должны быть применены миграции. Создавать учётную запись в Compose перед переносом не нужно. Команда перенесёт существующие учётные записи вместе с паролями и правами доступа.

## Подготовка

1. Остановите локальные сервер Django и обработчик PDF. Сохраните вне репозитория совместную резервную копию `db.sqlite3` и `private-media/`. Если после остановки рядом с базой остались `db.sqlite3-wal` или `db.sqlite3-shm`, включите их в ту же копию.
2. Подготовьте `.env` по [инструкции запуска](../README.md#запуск-в-docker). Откройте терминал в корне проекта. Задайте в `archive_backup` абсолютный путь к каталогу резервной копии. Docker должен иметь доступ к этому пути, а пользователь приложения в контейнере — право читать базу и оригиналы. Каталог монтируется только для чтения.
3. Остановите сервисы, которые могут писать в целевое хранилище, соберите образ и запустите миграции.

```sh
archive_backup='/абсолютный/путь/к/резервной-копии'

docker compose stop web api indexer
docker compose build api
docker compose up -d --wait db
docker compose run --rm --no-deps migrate
```

## Проверка и перенос

Выполните предварительную проверку. Команда создаст временную копию SQLite, обновит её схему и проверит связи, наличие файлов и их SHA-256. Она выведет количество записей по таблицам и количество оригиналов.

```sh
docker compose run --rm --no-deps -v "$archive_backup:/source:ro" api \
  python manage.py transfer_archive \
  --source-db /source/db.sqlite3 --source-media /source/private-media
```

После успешной проверки запустите перенос и поднимите Compose.

```sh
docker compose run --rm --no-deps -v "$archive_backup:/source:ro" api \
  python manage.py transfer_archive \
  --source-db /source/db.sqlite3 --source-media /source/private-media --apply

docker compose up --build -d --wait
```

Войдите в приложение под прежней учётной записью. Сверьте количество документов, откройте несколько оригиналов, проверьте свои предметные области и поиск по тексту. Сохраните резервную копию SQLite и медиа после проверки. Оригиналы в томе и временная копия SQLite требуют свободного места на диске Docker.

## Если команда остановилась с ошибкой

При сообщении о непустой целевой базе проверьте, что запущен нужный проект Compose. Для быстрого повторного запуска после прерывания используйте ту же резервную копию. Команда использует ранее записанные оригиналы, если целевая база пуста и все пути и хеши совпали. При несовпадении или отсутствии файла сначала проверьте исходную копию и выбранный том. Незавершённая попытка может оставить временный каталог `.archive-transfer-*` внутри тома `originals`.
